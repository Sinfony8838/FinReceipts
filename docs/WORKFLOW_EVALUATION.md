# AI 工作流对照评测：2026-10-16

本轮使用真实模型与仓库保留的真实 SEC 财报快照，比较直接生成、错误提示修订和证据反馈修订。
这是金融数值问答上的小规模实验，不是游戏营销效果测试或全文事实正确率评测。

## 预登记与数据调整

原计划从现有 100 题、23 家公司题集中分层选取 30 题。固定样本后，SEC companyfacts 请求返回 HTTP 403；未使用缺失的事实运行模型。
经确认，改用已随仓库提供的 AAPL、NVDA 两份真实 SEC 快照，按 FY2023–2025 生成候选池；先按类别和 ID 排序，再使用随机种子 42，每类抽取 10 题。
最终为直接数值、比例、同比增长各 10 题，AAPL 19 题、NVDA 11 题。抽样在任何模型调用之前完成。

逐题核对快照中的概念、单位、数值、期间、申报编号及申报日期，独立复算题目证据行的比例/增长率。
这验证了题集与保留快照及算术的一致性；快照原始抓取时间未知，本轮也未重新连通 SEC 核实披露。
题集生成器和核验器共享指标定义，因此不是独立构建的外部评测集。原始数据来源与限制见[数据说明](data_sources.md)。

## 固定条件

- 模型：MiniMax-M3，Anthropic 兼容接口，标准服务、默认非思考模式；温度 0，最多输出 1,024 token。
- 本机原默认 M2.7 强制思考；现有客户端未保留完整思考块，因此在付费调用前排除该配置。未修改应用协议。
- 三种策略使用相同题目、事实、提示和生成设置；工具与模型升级关闭，修订上限 2 轮。各条件分别生成初始回答，不保证温度 0 时逐字确定。
- 所有支持的财务概念均保留供核验，不是仅把正确答案放进 lookup。日期过滤沿用现有 `as_of`，不宣称严格历史时点可用性。
- 成本按 [MiniMax 官方定价](https://platform.minimax.cn/docs/pricing/overview) 在 2026-10-16 核对。M3 标准短上下文输入/输出为 2.10/8.40 元每百万 token，缓存读取 0.42 元每百万 token。
- 每次 HTTP 尝试前按请求字节数加 4,096 的保守输入 token 估计及输出上限预留；重试另计，未知结果保留预留。运行阈值 8 元，为授权 10 元预算保留余量。该控制不是平台账单承诺。
- 探测需返回纯文本 `pong`。若出现思考或工具调用块、预算不足或实际用量超出预留边界，即停止；固定响应不替代真实结果。

## 指标口径

数值答案匹配率以每组全部题目为分母，读取最终 `ANSWER:` 数值并按既有单位/舍入容差与答案键比较；错误响应不删除。
无依据数字比例以成功回答中提取的数字为分母，年份排除；没有提取数字时不能据此认为内容正确。
记录每题调用、修订、耗时和 token；SDK 的简化计量未包含缓存读取 token，费用应以逐 HTTP 请求的原始 usage 台账单独复算，而非直接引用旧汇总字段。
检索事实反馈增加了模型可见信息，是证据辅助修正；不称为纯模型自我纠错、模型训练或营销提效。

## 复现

从仓库根目录使用锁定环境，配置普通 API 服务与密钥环境变量名称。不要将密钥写入文档、命令参数或结果文件。

```sh
python scripts/workflow_eval.py prepare --recorded --out runs/my-workflow-eval
python scripts/workflow_eval.py run --out runs/my-workflow-eval
```

运行前配置 `FINRECEIPTS_LLM_PROVIDER=anthropic`、`FINRECEIPTS_LLM_BASE_URL`、`FINRECEIPTS_LLM_API_KEY_ENV`。
模型和价格在辅助脚本中固定；未来复现必须重新核对价格、模型可用性和预算，不沿用本轮价格保证。
脚本拒绝覆盖已有目录/付费台账。只读准备不调用模型；`run` 会产生费用。

完整结果与复核结论在本轮调用完成后记录于下方。
