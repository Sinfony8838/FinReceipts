# 从生成答案到可复查交付：FinReceipts 工作流案例

FinReceipts 是金融研究场景下的 AI 生成与核验实践。目标是让使用者看到回答如何产生、哪些数字有依据、为什么需要修订，以及一次任务消耗了多少调用。

## 需求与交付

直接让模型回答财务问题，容易出现数值、公司、指标和期间错配。只增加一句“请仔细检查”无法说明修订是否有效。项目将流程拆成生成、确定性核验、反馈修订和结果交付；已有可选模型升级策略，本轮对照不启用。

交付包含浏览器问答与研究工作台、逐轮核验记录、HTML 证据收据和 JSON 导出。它们服务于同一任务的阅读与复查，不是多渠道营销分发功能。

## 方案选择与质量控制

- **分清生成和检查的职责。** 模型负责组织回答；规则与 SEC XBRL 事实负责核验可提取的数值，不让模型凭主观评价决定自己是否正确。
- **比较反馈方式。** 直接生成、仅提示错误、提供检索证据后修订分别评估。最后一种会向模型补充事实，必须称为证据辅助修正。
- **暴露检查盲区。** 同一金额放错公司或指标时，纯数字匹配仍可能通过。工作台并列展示数字匹配和有限年度语句核验，两种检查均不能证明全文正确。
- **控制重复工作。** 任务保存事实集、步骤和事件，已提交步骤可以恢复；刷新只读已存结果。未知结果的外部调用仍可能重复。
- **让使用者看懂结果。** 以中文摘要、结构化复核表、浅深色主题与响应式布局组织页面，技术详情按需展开。

## 如何把经验迁移到其他内容流程

可迁移的是需求分析、生成与核验分工、反馈对照、成本记录和人工复查方法。以游戏活动内容为例，可以先确定官方素材、活动期间、参与条件等必须准确的信息，再设计渠道表达与人工审核节点。

这只是应用设想：当前项目没有接入游戏素材、渠道发布、图像/视频生成、品牌语气评审或营销指标归因。财务数字规则也不能直接判断剧情理解、创意质量或玩家接受度。
