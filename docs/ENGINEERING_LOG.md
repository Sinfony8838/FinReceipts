## 为什么选这条主线

参考简历已经覆盖了 LangGraph、多 Agent、SSE、检查点、检索与审核循环。
仅增加 Agent 数量，很难形成可追问的差异。FinReceipts 已有财务数值核验与证据收据，
适合深入回答三个问题：**恢复后用的还是同一份证据吗？一次失败会不会反复扣预算？
一个正确金额是否足以证明整句话正确？**

本轮的工程组合是：固定事实集、步骤持久化、预算先预留、并发执行隔离、可补读事件、
不调用模型的两种核验条件对照。它是项目的差异点，不宣称是新的学术算法或行业首创。

## 发现 → 修改 → 验证

| 问题 / 缺口 | 修改 | 验证与边界 |
|---|---|---|
| `verification_passed` 使用 `all([])`，有数字但无核验结果时返回真；旧测试甚至要求这种行为 | 必须存在非空 audit；保留最终数值要求 | 修订 `test_verification_passed_gate`；无数字诊断也必须失败 |
| `_answer_node` 原地修改 `Usage`，浅拷贝字典仍共享每个模型的 Usage | 深拷贝总量和分模型用量 | 测试旧 checkpoint 用量不因后续回答而变化 |
| HTTP/SSE 生命周期内的内存状态不能恢复 | 新增 SQLite RunStore；JSON checkpoint 和事件同事务提交 | 重建服务后从 verify 继续，不再调用模型或数据源 |
| 并发请求可能重复推进 | expected_revision 比较交换、事务领取 lease、随机 worker token、过期检查 | 两个线程竞争只有一个成功；取消及过期恢复后旧 worker 无法提交 |
| 模型返回前进程失败可能使调用不计入预算 | 调度前持久化占用；恢复不返还未知调用 | 异常后恢复，预算耗尽时不再发模型调用；不能等同实际账单或 SDK 网络重试次数 |
| 每次核验重新读 provider，恢复时可能换了一批事实 | 创建时将请求期间及同比前期事实编码入数据库，记录 SHA-256 | 创建后清空外部 provider，核验仍使用相同证据 |
| 模型可能请求另一家公司、年份或扩展参数 | 固定可用工具与参数范围；工具调用计入独立预算 | 错公司、越界年份、布尔年份、额外 URL 参数负例均拒绝 |
| 代码或 provider 更换后继续旧流程含义不明 | 保存 Python 源文件与核心依赖摘要、provider 配置摘要；推进前比较 | 不一致返回冲突，不领取步骤、不调用模型 |
| 数字匹配容易被理解成整句可信 | 保存 numeric-only 语义；新增同证据 counter-audit 展示 bounded annual 差异 | 六个手写案例：正常语句、错指标、错公司、错年份、裸数字、无数字 |
| SSE 重连没有游标 | 持久化序号与 `Last-Event-ID`；读端点只补读历史 | API 重连返回连续的剩余事件，无新模型调用；这是有限补读流，不是后台常驻推送 |
| 日志无法独立复查 | JSON 导出、事件哈希链、离线校验脚本和外部 anchor 参数 | 修改请求、事实、状态、事件、截断事件均失败；链不是数字签名 |
| 原 API 默认监听全部网卡 | CLI 默认改为 `127.0.0.1` | 本机启动验收；Docker 显式配置行为未据此推断 |
| 依赖只有下限，隔天安装可能变化 | 加入 `uv.lock`，CI 改用 `uv sync --locked` | 本地锁文件校验与回归；远端 Linux CI 需在提交到 GitHub 后单独查看 |
| Windows 缺少创建 symlink 权限导致既有安全测试环境失败 | 只对 WinError 1314 跳过该一项，其他异常继续失败 | Linux CI 保留原始符号链接逃逸测试；不把本机 skip 当作通过 |

保持金融研究功能与业务接口不变，调整中英文首页，突出需求、生成与复核流程、证据交付和实验取舍。

实施中发现并处理了三个问题：

1. SEC 在线请求返回 403。保留原 30 题选择记录，经用户确认改用已有 AAPL/NVDA 真实快照；先固定新样本，再调用模型，明确来源核对不是本轮重新获取。
2. 本机 M2.7 配置强制思考，而现有客户端没有完整回传思考块。核对官方协议后选用同服务的 M3 非思考配置，所有条件一致；未扩展业务协议。评测辅助传输层首次初始化还暴露 SDK 已使用 httpx2，改为挂接 SDK 自带传输层，失败初始化没有产生调用。
3. 原评测汇总遗漏缓存读取 token。保留原始汇总，新增逐 HTTP 尝试的预算及用量台账，单独复算成本；未知响应保留预留，重试不能绕过额度。

评测辅助脚本增加 10 项离线测试，覆盖分层抽样、来源篡改、答案键算术、预算阈值、重试预留、协议异常和超额用量停止。
本轮全仓离线测试 643 passed / 1 skipped，跳过仍为 Windows 符号链接权限；Ruff 与格式检查通过。
本轮未修改界面，因此没有把历史 64 组布局检查描述为本轮重跑。

样本与完整模型结果见[本轮评测](WORKFLOW_EVALUATION.md)，可投递版本见[简历材料](RESUME_AI_MARKETING.md)。

最终三条件数值匹配分别为 21/30、17/30、30/30，调用为 30、63、68 次。错误提示条件的无依据数字减少但匹配率下降，证据反馈提高匹配却增加调用，并仍有正文数字未获支持。
保留这些差异，不将结果包装成全文正确或人工提效。162 次含探测请求按缓存分项估算约 0.27 元，保守台账约 0.37 元。
