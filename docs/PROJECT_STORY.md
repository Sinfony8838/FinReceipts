## 从核对数字到控制执行

财务回答可能引用了真实文件，却把金额放在错误的指标或期间下。FinReceipts 从这一具体问题出发：
将模型生成、确定性核验与证据展示分开，让同一个核验结果既能被人检查，也能驱动修订和模型路由。

早期版本完成 SEC XBRL 查询、金额匹配、LangGraph 修订流程和 HTML 收据。
反馈分为错误标记和附带检索值的证据反馈，避免把后者的收益误解成纯模型自纠错。
历史实验的条件、统计分母和成本假设保留在[评测来源](EVALUATION_NOTES.md)。

## 把运行状态也纳入证据

0.1.0 进一步处理执行可靠性：创建任务时固定财务事实；每步提交 JSON 状态和事件；
调用前占用预算；通过状态版本和租约拒绝并发旧结果；中断后明确确认，再从已提交边界继续。
这使演示可以回答“刷新会不会重跑”“恢复会不会重置预算”“迟到结果还能不能覆盖状态”等问题。

对照复核使用同一份回答和证据，分别执行数字匹配与受支持年度语句核验。
无需再调用模型，就能展示金额碰巧匹配与语义归属获得支持之间的区别。

工作台把回答、复核表与中文时间线放在主要区域，保留原始 JSON 和完整证据导出。
视觉改版的目标是让核验差异容易阅读，同时不让“任务完成”暗示“全文正确”。

## 当前边界

本项目使用 AI 辅助开发，设计、编排、审查及验证过程在代码与记录中展开。
上游数据和模型提供商保留各自贡献与条款。当前没有生产多租户隔离，
不承诺模型请求恰好一次，也不把固定事实摘要等同于历史公开时间证明。
